# AMP — Agent Memory Protocol

> AIエージェントの記憶を標準化する。

## AMPとは？

AMP (Agent Memory Protocol) は、AIエージェントが記憶を**保存・検索・共有・忘却**する方法を標準化するオープンプロトコルです。MCPがツール呼び出しを標準化したように、AMPは記憶を標準化します。

定義する内容:

1. **型** — 認知科学に基づく4種類の記憶型（エピソード・セマンティック・手続き・作業）
2. **ライフサイクル** — 記憶の生成・強化・統合・減衰・削除
3. **スキーマ** — 記憶レコードの標準JSONフォーマット（MemoryRecord）
4. **戦略** — プラガブルで合成可能な保存・検索アルゴリズム
5. **共有** — エージェント間の安全な記憶交換

```
エージェント → [AMP Provider] → 記憶ストア
                    ↕
            他のエージェント（AMP Interop経由）
```

## なぜ必要か？

今のAIエージェントは**健忘症**。各フレームワークが独自にメモリを実装し、ポータビリティも相互運用性もない。

- **AMP以前**: エージェントAがユーザーの好みを学習。エージェントBは何も知らない。フレームワーク変更？最初からやり直し。
- **AMP以後**: 記憶は型付き、スコア付き、バージョン管理済み、ポータブル。どのエージェント、どのバックエンドでも。

### AMPの位置づけ

```
MCP  → ツール呼び出しの標準化     （エージェントが何をできるか）
M2C  → メディア分析の標準化       （エージェントが何を理解したか）
AMP  → 記憶の標準化               （エージェントが何を覚えたか）← NEW
A2A  → エージェント間通信の標準化  （エージェントがどう話すか）
```

**エージェントの記憶**をカバーする既存の標準はない。AMPがこのギャップを埋めます。

## コアコンセプト

### 記憶の型

| 型 | 説明 | 例 |
|----|------|-----|
| **エピソード** | 出来事・会話・経験 | 「3月15日にCORSの問題をデバッグした」 |
| **セマンティック** | 事実・知識・好み | 「ユーザーはダークモードが好き」 |
| **手続き** | 手順・ワークフロー・パターン | 「デプロイ: `npm run build && cargo tauri build`」 |
| **作業** | 一時的・セッション限定 | 「現在動画#42を編集中」 |

### 記憶のライフサイクル

```
エンコード → 保存 → 検索 → 強化 → 統合 → 減衰 → 削除
                                    ↓
                                  変換
```

記憶は**生きたオブジェクト** — 使用で強化され、放置で減衰し、時間とともにより強い知識に統合されます。

### 信頼度スコアリング

すべての記憶に信頼度スコア（0.0〜1.0）:

- **ソース信頼度**: ユーザー発言(0.9) > 観察(0.8) > ツール結果(0.7) > 推論(0.5)
- **強化**: 確認のたびにスコア上昇
- **鮮度**: 最近の記憶ほど高スコア
- **減衰**: 未強化の記憶は時間とともに薄れる

### 戦略システム

タスクに応じて最適な記憶戦略を選択:

| 戦略 | 得意なこと | バックエンド例 |
|------|-----------|--------------|
| **Vector** | 「似た記憶を探す」 | Qdrant, Pinecone |
| **Graph** | 「Xに関連するものは？」 | Neo4j, SQLite |
| **Hierarchical** | 「今週何があった？」 | SQLite FTS5 |
| **Buffer** | 作業記憶 | インメモリ, Redis |

戦略は**合成可能** — Vector + Graphでセマンティック検索＋リレーション展開。

### アクセス制御

```
private → agent → team → public
```

PII分類を内蔵: `none` / `personal` / `sensitive` / `restricted`

### エージェント間共有

エージェントは完全な来歴追跡付きで記憶を共有可能。すべての記憶が完全な履歴を持つ — 誰が、いつ、どの操作で作成したか。

## アーキテクチャ

```
┌──────────────────────────────────────────────┐
│                 AMP レイヤー                  │
│                                              │
│  エージェントA ─┐              ┌─ エージェントB │
│               │              │              │
│               ▼              ▼              │
│  ┌──────────────────────────────────┐       │
│  │        Strategy Router            │       │
│  │  （クエリごとに最適戦略を選択）     │       │
│  └──────┬──────┬──────┬──────┬──────┘       │
│         │      │      │      │              │
│     Vector  Graph  Hier.  Buffer            │
│         │      │      │      │              │
│  ┌──────┴──────┴──────┴──────┴──────┐       │
│  │         AMP Provider              │       │
│  │  (MemU, Mem0, LangMem, 独自実装)  │       │
│  └──────────────────────────────────┘       │
│                                              │
│  Memory Exchange ←→ 他のAMP Provider         │
└──────────────────────────────────────────────┘
```

## 設計原則

| 原則 | 説明 |
|------|------|
| **Memory First** | 再発見する前にまず記憶を参照 |
| **Typed** | すべての記憶に認知科学ベースの型 |
| **Lifecycle-Aware** | 記憶は強化・減衰・統合される生きたオブジェクト |
| **Scored** | すべてに信頼度スコア |
| **Local-First** | 完全ローカル動作をサポート |
| **Interoperable** | どのエージェントフレームワーク、どのバックエンドでも |
| **Privacy-Aware** | アクセス制御とPII分類を標準搭載 |
